# Производственная аналитика ковровой фабрики (SAG)

Мой проект по аналитике реального производства — ковровой фабрики с двумя заводами, ANTP (Самарканд) и XIVA (Хива). Взял сырые выгрузки из SAP за 2024–2025 годы и прошёл весь путь: почистил данные, собрал базу, построил дашборды и добавил несколько графиков на Python, которых в Power BI не сделать.

**Путь данных:** Excel --> Python (pandas) --> PostgreSQL --> Power BI --> Python (matplotlib, plotly)

## Как всё устроено

Данные приходили из SAP в виде Excel-файлов — по выпуску, расходу джута, загрузке станков, остаткам и продажам. С каждым файлом работал по очереди: смотрел структуру, убирал служебные строки и мусор, чинил ошибки (например, pandas принимал код качества «NA» за пустую ячейку), проверял, что после чистки суммы сходятся с оригиналом.

Дальше залил всё в PostgreSQL — 8 таблиц, настроил связи между ними, проверил целостность запросами. И уже на базе строил визуализацию.

## Дашборды в Power BI

- **Производство** — что выпустили: по станкам, качествам, коллекциям, плотности
- **Расход джута** — сколько сырья ушло, по типам нити и заводам
- **Пиксели** — загрузка станков и как XIVA постепенно наращивал мощности
- **Продажи и остатки** — выручка, склады, оборачиваемость

## Графики на Python

Часть задач Power BI тянет плохо, поэтому взял Python:

- **Тепловая карта простоев** — сам ищет, где станок стоял несколько дней подряд
- **Солнечная диаграмма** — вся структура выпуска в одной картинке (завод → бердо → коллекция)
- **Диаграмма Парето (ABC-анализ)** — оказалось, 18 коллекций из 113 дают 80% продаж
- **Оборачиваемость** — на сколько месяцев хватит запаса в каждом магазине

## Что интересного вышло

- Основной выпуск — это всего две плотности (бердо 32 и 40), почти всё производство
- После запуска XIVA расход джута перераспределился между заводами
- 18 коллекций держат 80% продаж, остальные почти не двигаются
- Нашлись магазины, забитые товаром на годы вперёд при почти нулевых продажах
